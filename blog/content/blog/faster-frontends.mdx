A performance budget turns a vague preference for speed into a constraint the team can discuss. It works best when each limit maps to an experience.

## Choose observable limits

| Resource | Initial budget | Why it matters |
| --- | ---: | --- |
| JavaScript | 120 kB compressed | Parsing and hydration |
| CSS | 40 kB compressed | Render-blocking work |
| Hero image | 180 kB | Largest Contentful Paint |

## Split at interaction boundaries

Code splitting is most valuable when the deferred code belongs to a feature the reader may never use. A chart editor, configurator, or rich comment box is a better boundary than a tiny shared button.

```ts
const Editor = lazy(() => import('./editor'));
```

Measure after each meaningful change. A budget without a probe becomes documentation rather than a constraint.
